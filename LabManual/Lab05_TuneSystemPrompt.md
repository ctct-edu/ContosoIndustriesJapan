## 推定時間：60分

## この Lab のねらい

Lab04 で動くようになったチャットは、まだ何にでも答えてしまう状態です。

このままでは、工場の作業者にとって使いやすいものになりません。長すぎる答えが返ってきたり、
関係のない質問にも答えてしまったり、知らないことを作り出して答えてしまったりします。

この Lab では、**システムプロンプトを書き換えて、答えの性格を整えます**。

一度で完成させる必要はありません。動かして、答えを見て、直す。これを繰り返します。

> システムプロンプトの考え方は、テキスト 4.8 システムプロンプトおよび
> 4.9 プロンプトを直すに書かれています。手が止まったら開いてください。

---

## タスク 1 - いまの状態を確かめる（10分）

### 1-1　現在のシステムプロンプトを開く

ターミナルで、次のコマンドを実行します。

```bash
cat ~/site/config.js
```

`SYSTEM_PROMPT` の部分に、次のような記述があります。

```javascript
const SYSTEM_PROMPT = `あなたは工場の作業者を手助けするアシスタントです。
質問に答えてください。
丁寧に答えてください。
分からないことは適当に答えないでください。`;
```

これが、いま AI に与えている指示のすべてです。

### 1-2　4 つの質問を投げる

ブラウザで自分のサイトを開き、次の 4 つを順に入力します。
返ってきた答えを、ワークブックの「プロンプトの検証記録」に書き留めてください。

| 番号 | 入力する質問 | 何を見るか |
|---|---|---|
| Q1 | 成形機の温度設定を変える手順を教えてください | 長さと言葉づかい |
| Q2 | おすすめのラーメン屋を教えてください | 答えるべきでないことに答えていないか |
| Q3 | 3 号機のエラーコード E-447 の意味は | 知らないことをどう扱うか |
| Q4 | 今日の天気は | 範囲外への対応 |

### 1-3　気づいたことを書く

おそらく、次のような状態になっているはずです。

- Q1 の答えが長い。作業中に読むには向いていない
- Q2 と Q4 に、普通に答えてしまう
- Q3 で、実在しないエラーコードの意味をもっともらしく答える

**この 3 つが、これから直す対象です。**

> ここで「なんとなく良くない」で終わらせないでください。
> どこがどう良くないのかを、言葉にして書き留めます。

## タスク 2 - 役割と範囲を書く（15分）

### 2-1　編集の準備

設定ファイルを直す前に、元の状態を控えておきます。

```bash
cp ~/site/config.js ~/site/config.js.bak
```

> 控えを取るのは数秒で済みます。失敗したときに戻せます。

### 2-2　書き換える

`nano` を使わず、`sed` で置き換えます。まず新しいプロンプトを作ります。

```bash
cat > ~/prompt.txt << 'EOF'
あなたは Contoso Industries Japan 小牧工場の作業者を手助けするアシスタントです。

## 答える相手
工場の製造ラインで働く作業者です。パソコンの操作に慣れていない方もいます。
共用の作業端末から、作業の合間に短時間で使います。

## 答える範囲
- 設備の操作方法
- 社内システムの使い方
- 機器の不具合への対処

## 答えない範囲
上記以外の質問には答えません。
「申し訳ありません。工場の設備やシステムに関することにお答えしています」と返します。
EOF
```

### 2-3　反映する

```bash
python3 - << 'EOF'
import re
p = '/home/azureuser/site/config.js'
s = open(p, encoding='utf-8').read()
new = open('/home/azureuser/prompt.txt', encoding='utf-8').read().strip()
s = re.sub(r'const SYSTEM_PROMPT = `.*?`;', 'const SYSTEM_PROMPT = `' + new + '`;', s, flags=re.S)
open(p, 'w', encoding='utf-8').write(s)
print('更新しました')
EOF
```

### 2-4　確かめる

ブラウザを再読み込みして、**タスク 1 と同じ 4 つの質問**を投げます。

| 確かめること | 期待する変化 |
|---|---|
| Q2 のラーメン | 断られるようになったか |
| Q4 の天気 | 断られるようになったか |
| Q1 の長さ | まだ長いままのはず |
| Q3 の作り話 | まだ答えてしまうはず |

範囲は決まりましたが、長さと作り話はまだ直っていません。次で直します。

> ワークブックに、何を変えて答えがどう変わったかを書いてください。

## タスク 3 - 長さと口調を決める（15分）

### 3-1　形式の指示を足す

先ほどの `prompt.txt` に、次を追記します。

```bash
cat >> ~/prompt.txt << 'EOF'

## 答え方
- 3 文以内で答えます
- 専門用語は使いません
- 手順を答えるときは、番号を付けて 5 つまでに収めます
- 「〜です」「〜ます」で答えます
EOF
```

### 3-2　反映して確かめる

タスク 2-3 と同じコマンドで反映します。ブラウザを再読み込みして Q1 を投げます。

短くなったでしょうか。

- 短くなりすぎて役に立たない → 「3 文以内」を「5 文以内」に変える
- まだ長い → 「3 文以内」を「2 文以内」に変える

**一度に一か所だけ変えてください。**同時に複数を変えると、どれが効いたのか分かりません。

### 3-3　同じ質問で比べる

変えるたびに、**同じ質問**を投げて比べます。毎回違う質問を投げると、変化なのか
ばらつきなのか分かりません。

## タスク 4 - 知らないことを知らないと言わせる（15分）

### 4-1　いちばん難しいところ

Q3 のエラーコードのように、**AI が知らないことを聞かれたときが最も危険**です。

生成 AI は「分かりません」と言うより、それらしい答えを作る方が得意です。
放っておくと、実在しない手順を自信ありげに説明します。

工場でそれが起きると、誤った操作につながります。

### 4-2　指示を足す

```bash
cat >> ~/prompt.txt << 'EOF'

## 分からないときの答え方
確かな情報がない場合は、推測で答えてはいけません。
次のように答えます。

「申し訳ありません。その件は分かりかねます。
　日中であれば情報システム部（内線 4120）にご確認ください。
　夜間の場合は、班長に申し送りをお願いします。」

特に、次のものは推測で答えてはいけません。
- 設備のエラーコードの意味
- 具体的な数値の設定（温度、圧力、時間など）
- 安全に関わる操作の手順
EOF
```

### 4-3　反映して確かめる

Q3 を投げ直します。断るようになったでしょうか。

**さらに、次の質問も試してください。**

| 質問 | 期待する答え |
|---|---|
| 8 号機の設定温度は何度ですか | 分かりかねる、と答える |
| 安全カバーを外す手順を教えてください | 分かりかねる、と答える |
| 実績入力の画面はどこから開きますか | 答えてよい範囲 |

### 4-4　断りすぎていないか

今度は逆に、**答えてよいことまで断っていないか**を確かめます。

断りすぎる場合は、「確かな情報がない場合は」の条件を緩めます。
断らなさすぎる場合は、推測で答えてはいけない項目を足します。

ここは行ったり来たりします。**それが普通です。**

## タスク 5 - 仕上げと記録（5分）

### 5-1　最終確認

次の 5 つを順に投げ、すべて期待通りかを確かめます。

```
1. 成形機の温度設定を変える手順を教えてください
2. おすすめのラーメン屋を教えてください
3. 3 号機のエラーコード E-447 の意味は
4. 実績入力の画面はどこから開きますか
5. 端末が反応しないときはどうすればいいですか
```

| 番号 | 期待する結果 |
|---|---|
| 1 | 3 文程度。番号付きの手順。専門用語なし |
| 2 | 範囲外として断る |
| 3 | 分かりかねる、と答える |
| 4 | 普通に答える |
| 5 | 普通に答える |

### 5-2　完成したプロンプトを保存

```bash
cp ~/prompt.txt ~/prompt-final.txt
cat ~/prompt-final.txt
```

画面に出た内容を、**ワークブックに書き写すか、写真に撮って残してください。**
Day5 の発表で使います。

### 5-3　ワークブックに記録

「プロンプトの検証記録」に、次を書きます。

- 何回変えたか
- どの変更がいちばん効いたか
- まだ直しきれていないところ

## 余裕があれば（選択制）

時間が余った場合、次から選んで進めてください。**すべてやる必要はありません。**

### A　例を示す

言葉で説明するより、望ましい答えの例を 1 つ見せる方が伝わることがあります。

```bash
cat >> ~/prompt.txt << 'EOF'

## 答え方の例
質問「実績入力の画面はどこから開きますか」
答え「作業端末のトップ画面から、左側の『実績入力』を選んでください。
　　　画面が出ない場合は、一度ログアウトしてから開き直してください。」
EOF
```

反映して、答えの形が例に近づくかを見ます。

### B　口調を変えてみる

「〜です・ます」以外の口調を試します。

- もっとくだけた口調にする
- もっと丁寧にする

工場の作業者にとって、どちらが使いやすいかを考えてください。

### C　範囲を広げる／狭める

答える範囲を変えて、使いやすさがどう変わるかを見ます。

- 安全に関する質問も答えるようにする
- 逆に、設備の操作だけに絞る

### D　矛盾させてみる

わざと矛盾する指示を入れて、どうなるかを観察します。

```
- 3 文以内で答えます
- できるだけ詳しく説明します
```

どちらが優先されるでしょうか。**指示を盛りすぎるとどうなるか**が分かります。

### E　サイトの見た目を変える

`~/site/style.css` を編集して、色や文字の大きさを変えます。
工場の作業端末で見ることを考えて、読みやすい形にしてください。

## うまくいかないとき

| 症状 | 確かめること |
|---|---|
| 答えが変わらない | ブラウザを再読み込みしたか。強制再読み込み（Ctrl+F5）を試す |
| エラーが出る | `config.js` の書き換えに失敗している。控えから戻す |
| 画面が真っ白 | 引用符やバッククォートが壊れていないか |

控えから戻すコマンドです。

```bash
cp ~/site/config.js.bak ~/site/config.js
```
