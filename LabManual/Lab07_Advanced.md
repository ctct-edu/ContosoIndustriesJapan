## A　長さを調整する

Lab05 で決めた「3 文以内」が、自分たちの素材に合っているかを確かめます。

- 短くなりすぎて役に立たない → 「3 文以内」を「5 文以内」に変える
- まだ長い → 「3 文以内」を「2 文以内」に変える

数字は、次のコマンドで変えられます（例：3 文以内 → 5 文以内）。

```bash
sed -i 's/3 文以内/5 文以内/' ~/prompt.txt
```

## B　断りすぎを直す

**答えてよいことまで断っていないか**を確かめます。次の質問を投げます。

```
実績入力の画面はどこから開きますか
```

```
端末が反応しないときはどうすればいいですか
```

- 断りすぎる場合は、「確かな情報がない場合は」の条件を緩めます（例：「参考資料に書かれていない場合は」に変える）
- 断らなさすぎる場合は、推測で答えてはいけない項目を足します

ここは行ったり来たりします。**それが普通です。**

## C　例を示す

言葉で説明するより、望ましい答えの例を 1 つ見せる方が伝わることがあります。

```bash
cat >> ~/prompt.txt << 'EOF'

## 答え方の例
質問「実績入力の画面はどこから開きますか」
答え「作業端末のトップ画面から、左側の『実績入力』を選んでください。
　　　画面が出ない場合は、一度ログアウトしてから開き直してください。」
EOF
```

反映して、答えの形が例に近づくかを見ます。

## G　素材の組み合わせを変える

Lab06 で追加した素材のチェックを、素材パネル（[デバッグ] ボタンで開く）で入れたり外したりして、組み合わせによる違いを比べます。

- 全部入れたときと、いちばん大事な 2 つだけのとき
- 「基本」の素材だけのときと、詳しい素材も入れたとき

素材を減らすと、応答が速くなり、料金も下がります。**少ない素材で同じ答えが出せるなら、そのほうが良い設計です。**

## H　サイトの見た目を変える

`/var/www/html/style.css` を編集して、色や文字の大きさを変えます。
工場の作業端末で見ることを考えて、読みやすい形にしてください。

`style.css` の先頭には、変えてよい場所と、生成 AI への頼み方が書いてあります。色や文字の大きさは、`:root` の変数（`--accent` など）を変えるだけで変わります。
生成 AI に頼むときは、`style.css` の中身を貼り付け、「`:root` の変数だけを変えて、〇〇な見た目にしてください」と伝えると、画面が崩れにくくなります。

```bash
sudo cp /var/www/html/style.css ~/style.css.bak
sudo nano /var/www/html/style.css
```

> 注：保存は `Ctrl + O` → `Enter`、終了は `Ctrl + X` です（Lab03 と同じ操作です）。
> 元に戻すときは `sudo cp ~/style.css.bak /var/www/html/style.css` を実行します。

## I　言語を増やす・絞る

Lab05 のタスク 6、Lab06 のタスク 5 で足した言語の指示を、変えて比べます。

- 対象の言語を 1 つ増やす（例：韓国語。指示文は、その言語で書きます）
- 対象の言語を絞る（例：英語だけ）
- 断り文を、言語ごとに書き直す

同じ質問を、何回か投げてください。**言語は、毎回同じとは限りません。** ばらつきも、記録に書きます。

> 注：ミャンマー語などは、nano と mini では不安定です。試す場合は、うまくいかなくても、記録に残せば成果になります。
