## 推定時間：20分

## この Lab のねらい

Lab02 で接続したサーバーの中を、コマンドだけで操作します。サーバーには画面もマウスもありません。

この Lab では、**実際の仕事に近い場面**で練習します。

> 場面：工場の作業端末のログ（記録）が、サーバーに届いています。「昨夜、端末が動かなくなった」という問い合わせの原因を、ログから調べて、**調査メモ**にまとめます。

使うコマンドは、Lab03 以降でそのまま使います。

> 注：このサーバーは、自分専用の仮想マシンです。コマンドを打ち間違えても、ほかの人には影響しません。ただし、この練習では `rm`（ファイルを削除するコマンド）は使いません。打たないでください。

### 先に知っておくと楽になる操作

| 操作 | 内容 |
|---|---|
| `Tab` キー | 入力の途中で押すと、ファイル名を補完してくれます。打ち間違いが減ります |
| `↑` キー | 直前に打ったコマンドを呼び出します。同じコマンドを打ち直さずに済みます |
| `Ctrl + C` | 実行中のコマンドを止めます。画面が戻らなくなったら押します |
| `clear` | 画面をきれいにします |

## タスク 1 - 場所を確認して、動き回る（pwd、ls、cd）

1. Lab02 で接続した PowerShell の SSH セッションを開き、`azureuser@vm-intern-YYMMDD-NN:~$` のプロンプトが表示されていることを確認します。

    > 注：SSH が切れている場合は、Lab02 のタスク 3 の手順で、もう一度接続してください。

2. いまいる場所を確認します。

    ```bash
    pwd
    ```

    `/home/azureuser` と表示されます。これが自分専用のフォルダー（ホームディレクトリ）です。プロンプトの `~` も、同じ場所を表します。

3. ファイルの一覧を、詳しく、隠しファイルも含めて表示します。

    ```bash
    ls -la
    ```

    `.bashrc`、`.profile` など、名前が `.` で始まるファイルが表示されることを確認します。

    > 注：`-l` は詳しい表示、`-a` は `.` で始まる隠しファイルも含めた表示です。このような `ls` の後ろに付ける指定を「オプション」といいます。

4. `/etc`（サーバーの設定ファイルの置き場所）に移動して、戻ります。

    ```bash
    cd /etc
    pwd
    cd ~
    pwd
    ```

    `/etc` と表示されたあと、`/home/azureuser` に戻ることを確認します。

## タスク 2 - 練習用のファイルを取得する（git clone）

練習用のログやメモは、GitHub のリポジトリに用意してあります。Lab03 で使うサンプルサイトも、同じリポジトリに入っています。

1. ホームディレクトリで、リポジトリを取得します。

    ```bash
    cd ~
    git clone https://github.com/ctct-edu/ContosoIndustriesJapan.git
    ```

    > 注：`git` が入っていない場合は、`sudo apt install git -y` を先に実行してください。

2. 練習用のフォルダーに移動して、中身を確認します。

    ```bash
    cd ~/ContosoIndustriesJapan/cliPractice
    ls -l
    ```

3. 次の 3 つのファイルがあることを確認します。

    | ファイル | 内容 |
    |---|---|
    | `server.log` | 工場の作業端末のログ（1 日分） |
    | `notes-template.txt` | 調査メモのひな形 |
    | `config-sample.txt` | 接続設定のサンプル（値はすべてダミー） |

## タスク 3 - ログの中身を見る（cat、head、tail、wc）

1. ログ全体を表示します。

    ```bash
    cat server.log
    ```

    大量の行が流れます。このように、**全部を目で追うのは現実的ではありません。**

2. 先頭の 5 行だけを表示します。

    ```bash
    head -5 server.log
    ```

3. 末尾の 5 行だけを表示します。

    ```bash
    tail -5 server.log
    ```

    > 注：ログは、新しいものが下に追加されます。**最近の出来事を知りたいときは、`tail` を使います。**

4. 行数を数えます。

    ```bash
    wc -l server.log
    ```

5. `87 server.log` と表示されることを確認します。

6. 1 行の読み方を確認します。

    ```
    2026-10-27 02:10:39 [ERROR] pc-line03 timeout after 5s
    ```

    **日付　時刻　[重要度]　端末の名前　内容**の順に並んでいます。重要度は、`INFO`（通常）、`WARN`（注意）、`ERROR`（異常）の 3 段階です。

    > 注：`clear` で画面を整理しておくと、以降の結果が見やすくなります。

## タスク 4 - 必要な行だけを探す（grep）

1. `ERROR` を含む行だけを表示します。

    ```bash
    grep ERROR server.log
    ```

2. 8 行表示されることを確認します。

3. 件数だけを数えます。

    ```bash
    grep -c ERROR server.log
    ```

    `8` と表示されます。

4. 条件を重ねます。`|`（パイプ）は、「左の結果を、右のコマンドに渡す」という意味です。

    ```bash
    grep ERROR server.log | grep pc-line03
    ```

5. 表示された行数を確認します。

    ```bash
    grep ERROR server.log | grep -c pc-line03
    ```

    `7` と表示されます。

    > 注：8 件の異常のうち、7 件が `pc-line03` の端末で起きています。**ログを絞り込むと、原因の手がかりが見えてきます。**

6. `INFO` 以外（注意と異常）をすべて表示します。

    ```bash
    grep -v INFO server.log
    ```

    > 注：`-v` は「含まない行」を表示するオプションです。

## タスク 5 - 結果をファイルに残す（リダイレクト）

1. `ERROR` の行だけを、ホームディレクトリの `errors.txt` に保存します。

    ```bash
    grep ERROR server.log > ~/errors.txt
    ```

    画面には何も表示されません。`>` は、「画面ではなく、ファイルに書く」という意味です。

2. 保存できたことを確認します。

    ```bash
    cat ~/errors.txt
    wc -l ~/errors.txt
    ```

3. `8 /home/azureuser/errors.txt` と表示されることを確認します。

    > 注：`>` は、すでにあるファイルを**上書き**します。ファイルの末尾に**追記**したいときは、`>>` を使います。

## タスク 6 - エディタでファイルを書く（nano）

サーバーでファイルを編集するときは、ターミナルの中で動くエディタ **nano** を使います。この Lab 以降の手順書でも、すべて nano を使います。

1. 調査メモのひな形を、自分のフォルダーにコピーします。

    ```bash
    cp ~/ContosoIndustriesJapan/cliPractice/notes-template.txt ~/notes.txt
    ```

2. nano で開きます。

    ```bash
    nano ~/notes.txt
    ```

3. 画面の下に、操作の一覧（`^X 終了` など）が表示されます。`^` は `Ctrl` キーのことです。

    | キー | 内容 |
    |---|---|
    | 矢印キー | カーソルを動かします（マウスは使えません） |
    | `Ctrl + O`、`Enter` | 保存します |
    | `Ctrl + X` | 終了します（保存していなければ、保存するか聞かれます） |
    | `Ctrl + W` | 文字を検索します |
    | `Ctrl + K` | カーソルのある 1 行を切り取ります |
    | `Ctrl + U` | 切り取った行を貼り付けます |

4. `調査した人:` の後ろに、自分の名前を入力します。

5. `(ここに書く)` の行を、矢印キーで移動して選び、文字を消して、**ひとまず「ここに調べた結果を書く」** と入力します。

6. `Ctrl + O` を押し、`Enter` を押して保存します。

7. `Ctrl + X` を押して、nano を終了します。

8. 保存できたことを確認します。

    ```bash
    cat ~/notes.txt
    ```

    自分の名前が入っていることを確認します。

    > 注：保存せずに終了したときは、`Save modified buffer?` と聞かれます。`Y` を押して `Enter` で保存、`N` で破棄します。

## タスク 7 - 設定ファイルを、安全に書き換える（cp、nano、diff）

サーバーの設定ファイルは、**書き換える前に、控えを取る**のが基本です。失敗したとき、元に戻せるからです。Lab05 でも、この手順を使います。

1. 設定のサンプルを、自分のフォルダーにコピーします。

    ```bash
    cp ~/ContosoIndustriesJapan/cliPractice/config-sample.txt ~/config.txt
    ```

2. 書き換える前に、**控え**を取ります。

    ```bash
    cp ~/config.txt ~/config.txt.bak
    ```

3. nano で開きます。

    ```bash
    nano ~/config.txt
    ```

4. `MAX_SENTENCES=3` を、**`MAX_SENTENCES=5`** に書き換えます。保存（`Ctrl + O`、`Enter`）して、終了（`Ctrl + X`）します。

5. 控えと、書き換えたあとを比べます。

    ```bash
    diff ~/config.txt.bak ~/config.txt
    ```

6. 次のように、**違いのある行だけ**が表示されることを確認します。

    ```
    4c4
    < MAX_SENTENCES=3
    ---
    > MAX_SENTENCES=5
    ```

    > 注：`<` が控え（元）、`>` が書き換えたあとです。**意図した行だけが変わっているか**を、このようにして確かめます。

7. 失敗したと仮定して、控えから元に戻します。

    ```bash
    cp ~/config.txt.bak ~/config.txt
    grep MAX_SENTENCES ~/config.txt
    ```

8. `MAX_SENTENCES=3` に戻っていることを確認します。

    > 注：このファイルの `API_KEY` は、ダミーの値です。**本物の接続設定（Lab04 で扱います）には、本物の鍵が入ります。** `cat` で画面に表示したり、画面を共有したりするときは、注意してください。

## タスク 8 - ファイルの権限を確認し、絞る（ls -l、chmod）

1. 設定ファイルの権限を確認します。

    ```bash
    ls -l ~/config.txt
    ```

2. 行の先頭に、`-rw-r--r--` のような表示があることを確認します。

    > 注：この表示は、**「だれが、何をできるか」**を表します。`rw-` が持ち主、続く `r--` が同じグループ、最後の `r--` がその他の人です。`r` は読む、`w` は書く権限です。環境によって、表示は少し異なります。

3. **持ち主以外が読めないように**します。

    ```bash
    chmod 600 ~/config.txt
    ls -l ~/config.txt
    ```

4. 行の先頭が `-rw-------` に変わったことを確認します。

    > 注：鍵が入っているファイルは、このように、持ち主だけが読み書きできる状態にします。

## タスク 9 - 管理者の権限で実行する（sudo）

1. パスワード情報が入っているファイルを見ようとします。

    ```bash
    cat /etc/shadow
    ```

2. `Permission denied` と、拒否されることを確認します。

    > 注：一般の利用者には、このファイルを見る権限がありません。エラーではなく、意図した動作です。

3. `sudo` を付けて実行します。

    ```bash
    sudo cat /etc/shadow
    ```

4. 今度は中身が表示されることを確認します。

    > 注：`sudo` は「この一回だけ、管理者として実行する」という指示です。表示された内容は、画面の写真やスクリーンショットに残さないでください。

5. 画面を整理します。

    ```bash
    clear
    ```

## タスク 10 - 総合課題：ログを調べて、調査メモにまとめる

ここまでのコマンドを使って、**昨夜の問い合わせの原因を調べます。** ヒントは出しますが、コマンドは自分で考えて打ってください。

> 問い合わせ：「昨夜、ライン 3 の作業端末が動かなくなった。原因を教えてほしい」

1. 次の 4 つを、コマンドで調べます。

    | 調べること | 使うコマンドのヒント |
    |---|---|
    | 異常（ERROR）は、全部で何件か | `grep -c` |
    | いちばん異常が多い端末はどれか | `grep ERROR server.log` を見る |
    | 異常が起きたのは、何時から何時ごろか | 異常の行の、時刻を見る |
    | 異常の内容は何か（種類と件数） | `grep ERROR server.log | grep timeout` など |

2. 調べた結果を、`~/notes.txt` に書きます。`nano ~/notes.txt` で開き、「分かったこと」の欄に、**数字と事実**を書いてください。

3. 「次にやること」の欄に、**次に確かめたいことを 1 つ**書きます。

4. 保存して終了し、`cat ~/notes.txt` で確認します。

5. 答え合わせをします。

    <details>
    <summary>答え合わせ（まず自分で調べてから開いてください）</summary>

    | 調べること | 答え |
    |---|---|
    | 異常（ERROR）の件数 | 8 件 |
    | いちばん多い端末 | `pc-line03`（7 件）。残りの 1 件は `pc-line07` の「disk full」（14:05） |
    | 起きた時間帯 | 2 時 10 分から 2 時 52 分ごろ。その前の 2 時台前半に、`WARN` の `retry`（再試行）も出ている |
    | 内容 | `timeout after 5s`（5 件）、`connection refused`（2 件） |

    **書き方の例：**

    ```
    ## 分かったこと
    ・ERROR は 8 件。うち 7 件が pc-line03（2:10〜2:52）
    ・内容は timeout が 5 件、connection refused が 2 件
    ・pc-line07 の disk full（14:05）は、今回の件とは別の事象とみられる

    ## 次にやること
    ・pc-line03 の端末とネットワークの状態を、現場に確認する
    ```

    > 注：**「何件、どの端末、いつ、何が起きたか」を、数字で書く**ことが大切です。「たくさんエラーが出ていた」では、報告を受けた人が動けません。

    </details>

これで Lab02b は完成です。この SSH セッションは、そのまま開いておいてください。Lab03 でも使います。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| `command not found` と出る | コマンドの綴りの間違いです。打ち直してください。`Tab` キーでの補完も使えます |
| `No such file or directory` と出る | ファイル名か場所の綴りの間違いです。`pwd` と `ls` で、いまの場所と、ファイルがあるかを確認してください |
| `git clone` で `already exists` と出る | すでに取得済みです。`cd ~/ContosoIndustriesJapan && git pull` を実行してください |
| `grep` の結果が何も出ない | 大文字と小文字は区別されます。`ERROR` と大文字で打っているか確認してください |
| nano の画面から出られない | `Ctrl + X` を押します。保存するか聞かれたら、`Y`（保存）か `N`（破棄）を押して `Enter` を押します |
| 見慣れない画面（`vi`）が開いた | `Esc` を押してから `:q!` と入力して `Enter` を押すと、保存せずに閉じられます。`nano` と打ち直してください |
| 画面が戻らなくなった | `Ctrl + C` を押します |
| SSH が切れてしまった | Lab02 のタスク 3 の手順で、もう一度接続してください |
