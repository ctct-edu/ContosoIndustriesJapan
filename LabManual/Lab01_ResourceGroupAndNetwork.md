## 推定時間：60分

## タスク 1 - リソース グループを作成する

1. Azure Portal (https://portal.azure.com) にサインインします。

2. 「ホーム」の「Azure サービス」から [リソース グループ] をクリックします。

    > 注：一覧に表示されていない場合は、上部の「リソース、サービス、ドキュメントの検索」に `リソース グループ` と入力して選択します。

3. 「Resource Manager | リソース グループ」画面で、[＋ 作成] をクリックします。

4. 「リソース グループを作成します」画面の [基本情報] タブで、以下を設定します。

    | 項目 | 値 |
    |---|---|
    | サブスクリプション | 従量課金 |
    | リソース グループ名 | rg-intern-YYMMDD-NN |
    | リージョン | (Asia Pacific) Japan East |

    > 注：`YYMMDD` は実施日、`NN` は自分の番号に置き換えてください。

5. [レビューと作成] をクリックします。

6. [レビューと作成] タブで、以下の内容が表示されていることを確認します。

    | 項目 | 値 |
    |---|---|
    | サブスクリプション | 従量課金 |
    | リソース グループ名 | rg-intern-YYMMDD-NN |
    | リージョン | Japan East |

    > 注：「タグ」は「なし」のままで構いません。

7. [作成] をクリックします。

8. リソース グループの一覧に `rg-intern-YYMMDD-NN` が作成されていることを確認します。

    ![リソースグループの作成確認](./media/lab01-01.png)

## タスク 2 - 仮想ネットワークを作成する

1. Azure Portal 上部の検索バーに `仮想ネットワーク` と入力し、検索候補の「サービス」欄から [仮想ネットワーク] を選択します。

    ![仮想ネットワークの検索](./media/lab01-02.png)

2. 「ネットワーク基盤 | 仮想ネットワーク」画面で、[＋ 作成] をクリックします。

3. 「仮想ネットワークの作成」画面の [基本情報] タブで、以下を設定します。

    | 項目 | 値 |
    |---|---|
    | サブスクリプション | 従量課金 |
    | リソース グループ | rg-intern-YYMMDD-NN |
    | 仮想ネットワーク名 | vnet-intern-YYMMDD-NN |
    | リージョン | (Asia Pacific) Japan East |

    > 注：「リソース グループ」は一覧から、タスク1で作成した `rg-intern-YYMMDD-NN` を選択してください。

4. [次へ] をクリックし、[セキュリティ] タブに進みます。

5. [セキュリティ] タブで、以下がすべてチェックなし（既定値）であることを確認します。

    | 項目 | 値 |
    |---|---|
    | 仮想ネットワークの暗号化 | チェックなし |
    | Azure Bastion を有効にする | チェックなし |
    | Azure Firewall を有効にする | チェックなし |

    > 注：いずれも有料のオプション機能です。今回は使用しないため、既定値のまま進みます。

6. [次へ] をクリックし、[アドレス空間] タブに進みます。

7. [アドレス空間] タブで、以下の設定を確認します。

    | 項目 | 値 |
    |---|---|
    | アドレス空間 | 10.0.0.0/16 |
    | サブネット名 | default |
    | サブネットの IP アドレス範囲 | 10.0.0.0 - 10.0.0.255（/24） |

    > 注：既存の他リソースとアドレス空間が重複している旨の警告が表示される場合がありますが、ピアリング（VNet 同士の接続）を行わない限り問題ありません。今回は無視して進めます。

8. サブネット一覧の「default」をクリックし、「サブネットの編集」画面を開きます。

9. 以下を確認・設定します。

    | 項目 | 値 |
    |---|---|
    | サブネットの目的 | Default |
    | 名前 | default |
    | IPv4 アドレスの範囲 | 10.0.0.0/16 |
    | 開始アドレス | 10.0.0.0 |
    | サイズ | /24 (256 個のアドレス) |
    | プライベート サブネットを有効にする | チェックを外す |

    > 注：「プライベート サブネットを有効にする」が有効のままだと、VM が既定でインターネットに送信接続できません（2026年3月31日以降、新規VNetの既定仕様として追加された項目です）。Lab04 で nginx のインストールや AI Foundry への通信を行うため、必ずチェックを外してください。

10. [保存] をクリックします。

11. [タグ] タブに移動します。何も入力せず、そのまま [レビューと作成] タブに進みます。

12. 「検証に成功しました」と表示されることを確認し、以下の内容を確認します。

    | 項目 | 値 |
    |---|---|
    | サブスクリプション | 従量課金 |
    | リソース グループ | rg-intern-YYMMDD-NN |
    | 名前 | vnet-intern-YYMMDD-NN |
    | Azure リージョン | Japan East |
    | Azure Bastion | 無効 |
    | Azure Firewall | 無効 |
    | Azure DDoS ネットワーク保護 | 無効 |
    | アドレス空間 | 10.0.0.0/16 (65,536 個のアドレス) |
    | サブネット | default (10.0.0.0/24) (256 個のアドレス) |

13. [作成] をクリックします。

14. 「デプロイが完了しました」と表示されるまで待ちます。

    ![デプロイ完了](./media/lab01-03.png)

15. [リソースに移動] をクリックし、「概要」画面で以下が反映されていることを確認します。

    | 項目 | 値 |
    |---|---|
    | リソース グループ | rg-intern-YYMMDD-NN |
    | 場所 | Japan East |
    | アドレス空間 | 10.0.0.0/16 |
    | サブネット | 1 個のサブネット |

## タスク 3 - ネットワーク セキュリティ グループを作成する

1. Azure Portal 上部の検索バーに `ネットワークセキュリティグループ` と入力し、検索候補の「サービス」欄から [ネットワーク セキュリティ グループ] を選択します。

    ![NSGの検索](./media/lab01-04.png)

2. 「ネットワーク基盤 | ネットワーク セキュリティ グループ」画面で、[＋ 作成] をクリックします。

3. 「ネットワーク セキュリティ グループの作成」画面の [基本] タブで、以下を設定します。

    | 項目 | 値 |
    |---|---|
    | サブスクリプション | 従量課金 |
    | リソース グループ | rg-intern-YYMMDD-NN |
    | 名前 | nsg-intern-YYMMDD-NN |
    | リージョン | Japan East |

4. [次: タグ >] をクリックします。

5. [タグ] タブに移動します。何も入力せず、そのまま [次: 確認および作成 >] をクリックします。

    > 注：この画面のボタン表記は「確認および作成」です（VNetやリソースグループの「確認と作成」とは異なる表記なので注意してください）。

6. [確認および作成] タブで、「検証に成功しました」と表示されることを確認し、以下の内容を確認します。

    | 項目 | 値 |
    |---|---|
    | サブスクリプション | 従量課金 |
    | リソース グループ | rg-intern-YYMMDD-NN |
    | リージョン | Japan East |
    | 名前 | nsg-intern-YYMMDD-NN |

7. [作成] をクリックします。

8. 「デプロイが完了しました」と表示されるまで待ちます。

    ![デプロイ完了](./media/lab01-05.png)

9. [リソースに移動] をクリックし、「概要」画面で、既定のセキュリティ規則が以下のとおり作成されていることを確認します。

    **受信セキュリティ規則**

    | 優先度 | 名前 | ポート | プロトコル | ソース | 宛先 | アクション |
    |---|---|---|---|---|---|---|
    | 65000 | AllowVnetInBound | 任意 | 任意 | VirtualNetwork | VirtualNetwork | Allow |
    | 65001 | AllowAzureLoadBalancerInBound | 任意 | 任意 | AzureLoadBalancer | 任意 | Allow |
    | 65500 | DenyAllInBound | 任意 | 任意 | 任意 | 任意 | Deny |

    **送信セキュリティ規則**

    | 優先度 | 名前 | ポート | プロトコル | ソース | 宛先 | アクション |
    |---|---|---|---|---|---|---|
    | 65000 | AllowVnetOutBound | 任意 | 任意 | VirtualNetwork | VirtualNetwork | Allow |
    | 65001 | AllowInternetOutBound | 任意 | 任意 | 任意 | Internet | Allow |
    | 65500 | DenyAllOutBound | 任意 | 任意 | 任意 | 任意 | Deny |

    > 注：この時点では、SSH（ポート22）や HTTP（ポート80）の通信は許可されていません。この後の手順で受信規則を追加します。

## タスク 4 - 受信セキュリティ規則を追加する（HTTP・SSH）

1. NSG「nsg-intern-YYMMDD-NN」の「概要」画面で、左側メニューの [受信セキュリティ規則] をクリックします。

2. 既定の3規則（AllowVnetInBound、AllowAzureLoadBalancerInBound、DenyAllInBound）のみが表示されていることを確認します。

    ![受信セキュリティ規則一覧](./media/lab01-06.png)

3. [＋ 追加] をクリックします。

4. 「受信セキュリティ規則の追加」画面で、以下を設定します。

    | 項目 | 値 |
    |---|---|
    | ソース | Any |
    | ソース ポート範囲 | * |
    | 宛先 | Any |
    | サービス | HTTP |
    | 宛先ポート範囲 | 80（自動入力） |
    | プロトコル | TCP（自動選択） |
    | アクション | 許可 |
    | 優先度 | 100 |
    | 名前 | AllowHTTP |

5. [追加] をクリックします。

6. 再度 [＋ 追加] をクリックし、以下を設定します。

    | 項目 | 値 |
    |---|---|
    | ソース | Any |
    | ソース ポート範囲 | * |
    | 宛先 | Any |
    | サービス | SSH |
    | 宛先ポート範囲 | 22（自動入力） |
    | プロトコル | TCP（自動選択） |
    | アクション | 許可 |
    | 優先度 | 110 |
    | 名前 | AllowSSH |

7. [追加] をクリックします。

8. 受信セキュリティ規則の一覧に、以下の5件が表示されていることを確認します。

    | 優先度 | 名前 | ポート | プロトコル | ソース | アクション |
    |---|---|---|---|---|---|
    | 100 | AllowHTTP | 80 | TCP | 任意 | Allow |
    | 110 | AllowSSH | 22 | TCP | 任意 | Allow |
    | 65000 | AllowVnetInBound | 任意 | 任意 | VirtualNetwork | Allow |
    | 65001 | AllowAzureLoadBalancerInBound | 任意 | 任意 | AzureLoadBalancer | Allow |
    | 65500 | DenyAllInBound | 任意 | 任意 | 任意 | Deny |

    ![受信セキュリティ規則追加後](./media/lab01-07.png)

    > 注：「AllowSSH」の名前の左に注意アイコンが表示されます。これは、ソースを「Any」（すべてのIPアドレス）からのSSH接続を許可しているためです。本研修では学生が社外から接続するため許容しますが、実運用では接続元を絞り込むのが望ましいという点を補足しておくとよいでしょう。

## タスク 5 - サブネットに NSG を関連付ける

1. NSG「nsg-intern-YYMMDD-NN」の左側メニューで [サブネット] をクリックします。

2. 「結果なし。」と表示されていることを確認します（まだ関連付けられていない状態です）。

    ![サブネット関連付け前](./media/lab01-08.png)

3. [＋ 関連付け] をクリックします。

4. 「サブネットの関連付け」画面で、以下を設定します。

    | 項目 | 値 |
    |---|---|
    | 仮想ネットワーク | vnet-intern-YYMMDD-NN (rg-intern-YYMMDD-NN) |
    | サブネット | default |

5. [OK] をクリックします。

6. 「サブネットを保存しています」という通知が表示され、サブネット一覧に以下が表示されることを確認します。

    | 名前 | アドレス範囲 | 仮想ネットワーク |
    |---|---|---|
    | default | 10.0.0.0/24 | vnet-intern-YYMMDD-NN |

    ![サブネット関連付け完了](./media/lab01-09.png)

これでLab01（タスク1〜5：リソースグループ・VNet・NSG・受信規則・サブネット関連付け）は完成です。
